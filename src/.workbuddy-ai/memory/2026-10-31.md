## 构建修复（两个真实 bug）

1. `src/SqlAssist.Setup/SqlAssist.Setup.csproj` 的 `EmbedVsix` 目标原先 `BeforeTargets="PrepareForBuild"`，而 `PrepareForBuild` 早于 `ResolveReferences`（ProjectReference 在后者才编译）。所以**首次**（还没有 .vsix 时）构建必然报 `..\SqlAssist.Vsix\bin\Debug\net48\SqlAssist.vsix not found`，且根本不会去编译 Vsix 项目。
   修复：改为 `AfterTargets="ResolveProjectReferences" BeforeTargets="PrepareResources"`（PrepareResources 是第一个真正需要该嵌入资源的目标，且在 ResolveReferences 之后）。
2. `src/SqlAssist.Vsix/SqlAssist.Vsix.csproj` 导入 VSSDK targets 时写成 `$(NuGetPackageRoot)microsoft.vssdk...`（无分隔符）。本机 `NuGet.config` 的 `globalPackagesFolder` 是 `G:\nuget\packages`（**末尾无反斜杠**，与默认 `~\.nuget\packages\` 不同），拼接后变成 `...\packagesmicrosoft.vssdk...`，导入被静默跳过 → `GeneratePkgDef` / `CreateVsixContainer` 未定义 → 报 `MSB4057: The target "GeneratePkgDef" does not exist`，永远产不出 .vsix。
   修复：路径中显式加 `\`。

验证：`dotnet build src/SqlAssist.Setup -c Debug|Release` 从"无 .vsix"状态一次成功，产出 `SqlAssist.vsix` + `SqlAssistSetup.exe`（已内嵌 vsix）；`dotnet test` 864 通过。`build-setup.ps1` 走的正是 `dotnet build ...Setup -c Release`，因此该脚本现在可用。

## 新增：IntelliSense 开关

- `EditorOptions.IntelliSenseEnabled`（默认 true），持久化到 `settings.xml` 的 `<Editor IntelliSenseEnabled="true|false"/>`（`SqlAssistSettings.Parse/ToXml`，大小写不敏感，非法值回落默认）。
- `SettingsProvider.IntelliSenseEnabled`：节流的只读属性（每秒最多看一次文件），给热路径用。
- 生效点：
  - `SqlCompletionSource.InitializeCompletion` → 关闭时 `DoesNotParticipateInCompletion`（输入、Ctrl+Space 都不再弹列表）。
  - `TabCommandFilter`：Ctrl+Space 三个命令关闭时 `break` 交回 SSMS；`HandleTab` 在"代码片段"之后提前 `return false`（Tab 恢复普通缩进）；`TypeChar` 在 `Next.Exec` 后直接返回，不再补触发补全。
  - `ExpansionTip.Evaluate` → 关闭时不显示"按 Tab 可展开…"提示。
  - 不受影响：代码片段（Tab）、悬停表结构、F12 转到定义、INSERT 列高亮。
- 界面：选项 › 编辑器 页顶部新增加粗复选框"启用 IntelliSense（补全列表与 Tab 展开）"+ 说明，保存后立即生效（`Save()` 直接写 `_settings.Editor.IntelliSenseEnabled`）。
- 测试：`SettingsTests.IntelliSenseIsOnByDefaultAndKeepsWhatWasChosen`（含"关掉 IntelliSense 不影响列高亮"）；865 通过。
- README 功能表新增"IntelliSense 开关"一行。
